# RAG知识库问答流程 - 详细流程图文档

## 一、RAG系统整体架构与流程概览

本系统采用模块化设计，完整实现从知识库构建到智能问答再到多轮交互的全链路RAG能力。整体架构清晰划分为三大核心流程：**知识库索引流程（离线构建）**、**RAG问答流程（在线推理）** 和 **多轮对话流程**，各模块职责分明、协同高效。

以下为基于标准mermaid语法生成的完整流程图，可直接在支持mermaid渲染的Markdown环境中查看：


> **架构要点说明**：
> - **三区分离**：离线构建、在线推理、对话管理三大子图逻辑隔离，便于独立维护与扩展。
> - **异步解耦**：知识库构建中“发送异步任务”使用虚线边框与连线，体现非阻塞特性，保障系统响应性。
> - **流式反馈**：在线推理流程通过SSE实现流式输出，用户可实时接收AI生成内容。
> - **循环机制**：“继续提问”通过虚线箭头回连“用户提问”，清晰表达多轮对话的闭环逻辑。
> - **颜色语义**：沿用原图配色规范，黄色系表示通用处理，蓝色系表示向量操作，绿色表示状态节点，橙色表示用户交互，紫色表示会话控制。

## 二、三大核心流程模块详解

本系统由三大核心流程构成，分别承担知识准备、实时响应与交互管理职能。以下对各模块进行逐层解析，阐明其内部步骤功能及运行机制。

### 知识库索引流程（离线构建）

该流程为异步批处理任务，负责将原始文档转化为可供检索的向量数据库记录，共包含8个有序步骤：

- **文件上传**：前端支持PDF/Word格式文件上传，单文件大小限制为50MB，并进行类型合法性校验。
- **文本解析**：利用Apache Tika工具提取文档中的纯文本内容，同时清洗HTML标签、特殊字符等噪声信息，并处理空行。
- **保存元数据**：将原始文件存储至RustFS分布式文件系统，同时将文件名、路径、状态等元数据写入PostgreSQL关系型数据库，初始状态标记为PENDING。
- **发送异步任务**：将待处理任务推送到Redis Stream消息队列，立即向前端返回PENDING状态，实现非阻塞式调用，保障主流程响应速度。
- **文本分块**：采用Token TextSplitter算法对长文本进行切片，每块约500 tokens，相邻块间保留50 tokens重叠以维持语义连贯性。
- **批量向量化**：以10条为批次调用阿里云Embedding服务，将文本块转换为1024维语义向量，符合API调用限制。
- **存储向量**：将生成的向量存入pgvector扩展的PostgreSQL数据库，使用HNSW近似最近邻索引结构加速后续相似度搜索，并关联原始文档ID。
- **更新状态**：完成所有处理后，将任务状态更新为COMPLETED，记录成功生成的chunk数量，供前端轮询查询构建进度。

### RAG问答流程（在线推理）

此流程为同步实时响应链，处理用户自然语言提问并生成答案，涵盖7个关键环节：

- **用户提问**：用户输入问题，前端通过SSE（Server-Sent Events）建立长连接，系统保存用户消息至对话历史。
- **向量化查询**：调用Embedding API将用户问题转换为1024维语义向量，作为后续检索的查询依据。
- **向量相似度检索**：在pgvector中基于HNSW索引执行向量搜索，计算余弦相似度，返回最相关的Top-5文档片段。
- **元数据过滤**：根据当前会话绑定的知识库ID进一步筛选结果，支持跨多个知识库联合检索，提升准确性。
- **构建上下文**：将检索到的Top-K文档合并拼接，添加分隔符标识不同来源，并组装成完整提示词（prompt），供大模型使用。
- **LLM生成答案**：通过Spring AI ChatClient调用大语言模型，采用流式生成方式（SSE）逐步输出回答内容，实现实时推送至前端。
- **完成响应**：回答生成完毕后，保存AI侧消息记录，标记本次请求为完成状态，并关闭SSE连接释放资源。

### 多轮对话流程

该流程实现持续交互能力，支持用户在一次会话中多次提问，形成闭环逻辑：

- 用户首先创建新会话，选择目标知识库范围。
- 随后进入“用户提问”节点，触发RAG检索与生成流程。
- 每次问答结束后，系统自动保存当前对话记录至历史上下文。
- 用户可选择“继续提问”，重新回到“用户提问”节点发起新一轮查询。
- 整个过程通过虚线箭头标注“多轮”循环路径，体现其可重复执行特性，确保上下文一致性与交互连续性。

## 三、关键技术组件与系统特性

本RAG系统融合多种先进技术组件，构建起高效、稳定且具备持续交互能力的智能问答架构。以下从核心技术组件与核心系统特性两个维度进行系统性归纳，全面展现其工程实现基础与运行优势。

### 核心技术组件

系统集成了多个成熟的技术工具与框架，各组件在不同流程中承担关键角色，共同保障整体功能的完整性与高性能表现。

| 组件名称 | 所属流程 | 核心作用 |
| --- | --- | --- |
| Apache Tika | 知识库索引流程 | 用于提取PDF/Word等格式文件中的纯文本内容，并清洗HTML标签、特殊字符等噪声信息，确保输入数据质量 |
| RustFS | 知识库索引流程 | 分布式文件系统，负责存储原始上传的文档文件，提供高可用与可扩展的文件管理能力 |
| PostgreSQL | 知识库索引流程 | 关系型数据库，用于持久化保存文件元数据（如文件名、路径、状态）及chunk数量记录 |
| Redis Stream | 知识库索引流程 | 消息队列组件，实现异步任务解耦，将文本处理任务推送到后台执行，保障主流程非阻塞响应 |
| Token TextSplitter | 知识库索引流程 | 文本分块算法，按约500 tokens大小对长文本进行切片，保留50 tokens重叠以维持语义连贯性 |
| 阿里云 Embedding | 知识库索引流程 | 提供向量生成服务，将文本块转换为1024维语义向量，支持批次调用（每批10条） |
| pgvector | 知识库索引流程 | PostgreSQL的向量扩展插件，用于存储和检索高维向量，结合HNSW索引实现高效近似最近邻搜索 |
| HNSW 索引 | RAG问答流程 | 近似最近邻搜索算法，显著加速向量相似度计算过程，支持快速返回Top-5最相关文档片段 |
| Spring AI ChatClient | RAG问答流程 | 大语言模型调用客户端，封装LLM交互逻辑，支持流式生成（SSE）并实时推送回答至前端 |
| SSE (Server-Sent Events) | RAG问答流程 | 服务器推送技术，用于建立前端与后端的长连接，实现实时消息传输与低延迟反馈 |

### 核心系统特性

基于上述技术栈，系统展现出多项关键运行特性，使其在实际应用中具备良好的用户体验与工程适应性。

| 特性类别 | 实现机制 | 用户体验 |
| --- | --- | --- |
| **异步处理** | 文件上传后立即返回PENDING状态，通过Redis Stream异步触发后续解析与向量化任务，不阻塞主流程 | 用户无需等待耗时操作完成即可继续其他操作，提升系统响应速度与使用流畅度 |
| **流式响应** | 利用SSE技术，在LLM生成答案过程中逐步推送内容至前端，而非等待全部生成完毕 | 用户可实时看到AI“思考”与输出的过程，降低等待感知，增强交互沉浸感 |
| **多轮对话支持** | 每次问答后自动保存对话记录，并允许用户在同一会话中多次提问，形成闭环循环机制 | 支持上下文延续的深度交流，用户可在一次会话中围绕同一主题展开多轮追问 |
| **知识库隔离与联合检索** | 支持按知识库ID进行元数据过滤，既可独立检索单一知识库，也可跨多个知识库联合查询 | 用户可根据需求灵活选择信息范围，兼顾精准性与广度，提升检索准确性 |
| **状态可追踪** | 在PostgreSQL中记录任务状态（PENDING/COMPLETED）及chunk数量，前端可通过轮询获取构建进度 | 用户可清晰了解知识库构建进度，掌握系统运行状态，增强操作可控性与透明度 |
