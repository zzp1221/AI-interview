# 核心实体关系

## 一、核心实体概览

以下为系统中定义的三个主要数据实体，分别对应简历信息、面试会话状态与具体答题记录，构成典型的树状数据结构。

| 编号 | 实体名称           | 中文名称   | 描述                                                                 |
|------|--------------------|----------|----------------------------------------------------------------------|
| 1    | Resume             | 简历     | 存储候选人的简历基本信息，作为面试流程的起点和身份锚点               |
| 2    | InterviewSession   | 会话表   | 记录一次完整的面试会话实例，包含上下文状态、进度与最终评估结果         |
| 3    | InterviewAnswer    | 答案表   | 存储会话过程中每道题目的用户回答详情，包括评分与反馈信息               |

## 二、实体属性详细分析

### 1. Resume（简历）

该表作为整个数据模型的根节点，代表参与面试的候选人主体。

| 字段名 | 类型/约束 | 是否主键 | 是否外键 | 业务含义说明                                   |
|--------|-----------|----------|----------|------------------------------------------------|
| id     | 整数/字符串 | 是       | 否       | 唯一标识每份简历记录                           |
| ...    | —         | 否       | 否       | 表示存在其他未列出字段，可能包括姓名、联系方式等个人信息 |

> 注：`...`表示该表还包含若干非核心展示字段，不影响当前关系建模分析。

### 2. InterviewSession（会话表）

该表为核心中间实体，承载一次面试的全过程元数据与状态控制。

| 字段名                 | 类型/约束       | 是否主键 | 是否外键 | 业务含义说明                                                                 |
|------------------------|------------------|----------|----------|------------------------------------------------------------------------------|
| id                     | 整数/字符串      | 是       | 否       | 内部自增或生成的主键                                                         |
| sessionId (唯一)       | 字符串/唯一索引  | 否       | 否       | 全局唯一标识一次面试会话，用于外部引用和API交互                                |
| resumeId               | 整数/字符串      | 否       | 是       | 外键，关联至 `Resume.id`，建立简历与会话的归属关系                             |
| status / evaluateStatus| 枚举/字符串      | 否       | 否       | 当前会话所处阶段（如进行中、已完成、已取消）及评估状态                         |
| totalQuestions         | 整数             | 否       | 否       | 本次面试预设的总问题数量                                                     |
| currentQuestionIndex   | 整数             | 否       | 否       | 当前正在作答的问题索引（从0或1开始计数）                                       |
| questionsJson ← 题目快照 | JSON字符串       | 否       | 否       | 快照形式存储本次会话使用的全部题目内容，防止原始题库变动导致历史数据失真       |
| overallScore / overallFeedback | 数值/文本   | 否       | 否       | 综合评分与整体评语                                                           |
| strengthsJson / improvementsJson | JSON字符串 | 否       | 否       | 结构化存储候选人优势点与改进建议，便于前端展示                                 |

> 关键设计洞察：`questionsJson` 的“← 题目快照”注释表明系统采用**数据快照机制**，保障面试过程的一致性与可追溯性。

### 3. InterviewAnswer（答案表）

该表为叶节点实体，记录每一次回答的具体细节，是评分与反馈的基础来源。

| 字段名                | 类型/约束          | 是否主键 | 是否外键 | 业务含义说明                                                              |
|-----------------------|---------------------|----------|----------|---------------------------------------------------------------------------|
| id                    | 整数/字符串         | 是       | 否       | 主键                                                                      |
| session_id            | 字符串              | 否       | 是       | 外键，关联至 `InterviewSession.sessionId`，建立会话与答案的绑定关系         |
| question_index        | 整数                | 否       | 否       | 表示当前答案对应的问题序号，配合session_id形成唯一性约束                   |
| question / category   | 文本 / 字符串       | 否       | 否       | 问题原文内容及其分类（如技术类、行为类）                                    |
| userAnswer / score / feedback | 文本 / 数值 / 文本 | 否       | 否       | 用户提交的答案、机器或人工打分、针对性反馈                                 |
| referenceAnswer / keyPoints | 文本 / JSON数组   | 否       | 否       | 参考答案与评分关键要点，用于辅助评分与学习反馈                              |
| 唯一约束              | (session_id, question_index) | — | — | 确保同一会话中每个问题仅有一条答案记录，形成逻辑上的复合主键                |

> 设计重点：虽然`id`为主键，但实际业务唯一性由 `(session_id, question_index)` 联合保证，体现了**逻辑主键与物理主键分离**的设计思想。

## 三、实体间关系结构化描述

### 1. 关系拓扑图示（文字版）

```
Resume (1)
   │
   └─→ InterviewSession (N)
           │
           └─→ InterviewAnswer (N)
```

### 2. 详细关系说明

| 源实体           | 目标实体           | 关系类型 | 基数比 | 外键字段         | 引用目标字段     | 业务语义说明                                     |
|------------------|--------------------|----------|--------|------------------|------------------|--------------------------------------------------|
| Resume           | InterviewSession   | 一对多   | 1 : N  | resumeId         | Resume.id        | 一份简历可启动多次不同的面试会话                 |
| InterviewSession | InterviewAnswer    | 一对多   | 1 : N  | session_id       | InterviewSession.sessionId | 一次面试会话包含多个问题的回答记录               |

> 特别说明：`InterviewAnswer.session_id` 明确指向 `InterviewSession.sessionId` 而非 `id`，说明关联依据是**业务唯一标识符**而非内部主键，提升系统解耦性与接口兼容性。
